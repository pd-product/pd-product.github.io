{%- comment -%} Tradeoff tables, rendered from front matter rather than a Markdown table. The chosen column is identified by name, not by position, so the marker can never land on the wrong column. The check mark is written as an HTML entity to keep the source ASCII. `tradeoffs` is a LIST of tables even when a story has only one. A story that needs more than ~5 dimensions is meant to use a second table for a second decision rather than a taller one, and a list supports that without a later change to every existing story. The explicit ARIA roles below are NOT redundant markup and must not be "cleaned up". At 640px and below the stylesheet sets `display: block` on the table, thead, tbody, tr, th and td so each row can stack as labelled pairs. Browsers derive the implicit table/row/cell roles from the CSS display value, so that rule silently reduces the table to a run of generic blocks with no row or column relationships announced. Restating the roles keeps the structure readable at every width. This is the same bug class as the list-role rule elsewhere in this repo, where `list-style: none` drops the implicit list role in Safari with VoiceOver and every list therefore carries an explicit `role="list"`. A CSS display value that changes an element's implicit role has to be answered with an explicit role; that applies to this table exactly as it applies to lists. {%- endcomment -%} {%- for table in include.tradeoffs -%} {%- endfor -%}
